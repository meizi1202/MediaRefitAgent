# 检测功能切换并重新提取参数

## Context

当前 `handle_user_response` 在多轮对话中，会沿用上一轮的功能类型（`current_feature`）和已有参数。即使用户改变了需求（如从 convert 改为 compress），系统仍按 convert 的参数缺失逻辑处理，导致 compress 功能无法执行。

**问题场景：**
- Turn 1：用户说"转竖屏" → 识别为 convert，缺比例/策略
- Turn 2：用户说"压缩一下" → 本应切换到 compress，但 current_feature 仍为 convert

**期望行为：**
- 基于用户最新输入，先识别目标（功能类型）
- 若识别到的目标与历史相同 → 沿用现有逻辑（补充缺失参数）
- 若识别到的目标与历史不同 → 切换到新目标，重新提取参数
- 若识别不到目标 → 默认按同历史逻辑处理

## 实现方案

### 核心思路：识别优先 + 智能切换

1. **目标识别**：从用户最新输入中提取目标（功能类型），优先用 LLM 解析，UI 参数格式直接解析
2. **对比历史**：若识别到目标，对比与 `current_feature` 是否一致
3. **分支处理**：
   - 目标相同 → 继续参数补充逻辑
   - 目标不同 → 清除历史 explicit 参数，路由到 `analyze_intent` 重新解析
   - 未识别到 → 默认按同历史逻辑处理

### `_identify_target_from_input()`

```python
def _identify_target_from_input(user_input: str) -> Optional[str]:
    """从用户输入中识别目标（功能类型）

    Returns:
        功能类型字符串如 "convert", "compress", "trim" 等，或 None（未识别到）
    """
    # 1. 优先用 UI 参数格式解析（最准确）
    ui_params = _parse_ui_params(user_input)
    if ui_params.get("found"):
        return ui_params.get("feature")

    # 2. 自然语言：用 IntentParser 解析关键词
    from agent.nodes.analyze import IntentParser
    parsed = IntentParser.parse(user_input)

    # compress 相关关键词命中
    if parsed.get("compression_explicit") and parsed.get("compression"):
        return "compress"

    # convert 相关关键词命中
    if parsed.get("orientation_explicit") or parsed.get("strategy_explicit") or parsed.get("ratio_explicit"):
        return "convert"

    # 其他功能待扩展...

    return None
```

### 修改 `handle_user_response` 入口逻辑

```python

    identified_target = _identify_target_from_input(user_input)
    print(f"[DEBUG handle_user_response] identified_target={identified_target}, old_feature={old_feature}")

        state["compression_explicit"] = False
```
