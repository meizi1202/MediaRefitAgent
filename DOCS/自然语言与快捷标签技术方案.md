# 自然语言与快捷标签技术方案

## 概述

本文档梳理两种交互方式的技术实现方案：
1. **纯自然语言对话**：用户输入自然语言描述需求
2. **快捷标签 + 自然语言**：用户通过 UI 快捷标签选择参数，配合自然语言补充

---

## 一、纯自然语言对话

### 1.1 处理流程

```
用户输入 → analyze_intent() → _parse_ui_params() [未匹配]
         → LLM 解析 parse_intent() [可能失败]
         → 本地关键词解析 IntentParser.parse() [降级方案]
         → 更新状态 → 执行相应功能
```

### 1.2 核心代码文件

#### 1.2.1 入口：`backend/agent/nodes/analyze.py`

**方法**：`analyze_intent(state: VideoAgentState)`

**用途**：分析用户意图的主入口，协调 LLM 解析和本地解析

**前置代码**：
```python
# backend/agent/nodes/analyze.py 第 199-262 行
# 优先解析 UI 选择参数格式（纯自然语言时返回 found=False）
ui_params = _parse_ui_params(user_input)
if ui_params.get("found"):
    # ... 快捷标签路径，直接返回（不进入自然语言处理）
    return state
```

**核心代码**（第 264-440 行）：
```python
# 1. LLM 意图解析
_llm_parse_intent = _get_llm_parse_intent()
if _llm_parse_intent:
    parsed = _llm_parse_intent(user_input, llm, history=history)
    # 从 parsed 中提取参数...

# 2. 本地关键词解析作为降级（当 LLM 解析失败时）
local_parsed = IntentParser.parse(user_input)

# 3. 用本地解析补充 LLM 结果（用户明确提到的参数）
if local_parsed.get("orientation_explicit"):
    target_orientation = local_parsed["orientation"]
    orientation_explicit = True
if local_parsed.get("strategy_explicit"):
    strategy = local_parsed["strategy"]
    strategy_explicit = True
if local_parsed.get("ratio_explicit"):
    ratio = local_parsed["ratio"]
    ratio_explicit = True

# 4. 更新状态
all_params_provided = orientation_explicit and strategy_explicit
if all_params_provided:
    # 生成正确的回复
    llm_response = f"好的，使用{ratio_str}{orientation_str}和{strategy_str}策略，正在为您转换..."
```

**后置代码**：
```python
# 第 440-455 行
# 更新状态并进入下一节点
state["target_orientation"] = target_orientation
state["strategy"] = strategy
state["target_ratio"] = ratio
state["orientation_explicit"] = orientation_explicit
state["strategy_explicit"] = strategy_explicit
state["all_params_provided"] = all_params_provided
state["current_step"] = "detect_video"
return state
```

#### 1.2.2 LLM 解析：`backend/agent/langchain_agent.py`

**方法**：`parse_intent(user_input: str, llm: MinMaxLLM, video_info: dict, history: list)`

**用途**：调用 MiniMax LLM 解析用户意图

**核心代码**（第 98-149 行）：
```python
def parse_intent(user_input: str, llm: MinMaxLLM, video_info: dict = None, history: list = None) -> dict:
    # 第一步：识别工具类型
    tool_prompt = prompts.TOOL_RECOGNITION_PROMPT.format(
        history_context=history_context,
        user_input=user_input
    )
    tool_result = llm._generate([{"role": "user", "content": tool_prompt}])
    target_feature = tool_result.content.strip().lower()

    # 第二步：根据工具类型解析参数
    template = prompts.TOOL_PROMPTS[target_feature]
    param_prompt = template.format(...)
    param_result = llm._generate([{"role": "user", "content": param_prompt}])

    # 第三步：提取 JSON
    parsed = _extract_json(param_result.content)
    return _build_response(target_feature, parsed, all_params_provided)
```

#### 1.2.3 本地关键词解析：`backend/agent/nodes/analyze.py`

**类**：`IntentParser`

**方法**：`parse(cls, text: str) -> dict`

**用途**：通过关键词匹配解析方向、比例、策略

**核心代码**（第 25-91 行）：
```python
class IntentParser:
    ORIENTATION_KEYWORDS = {
        "portrait": ["竖屏", "portrait", "9:16", "9/16", "4:5", ...],
        "landscape": ["横屏", "landscape", "16:9", "16/9", "21:9", ...],
    }
    STRATEGY_KEYWORDS = {
        "smart_crop": ["智能裁剪", "AI裁剪", "ai crop", ...],
        "crop": ["裁剪", "crop", "切", "截"],
        "pad": ["填充", "pad", "黑边", "留边", "保持完整"],
        "rotate": ["旋转", "rotate", "旋转90度"],
    }

    @classmethod
    def parse(cls, text: str) -> dict:
        orientation, orientation_explicit = cls.parse_orientation(text)
        strategy, strategy_explicit = cls.parse_strategy(text)
        ratio, ratio_explicit = cls.parse_ratio(text)
        return {
            "orientation": orientation,
            "orientation_explicit": orientation_explicit,
            "strategy": strategy,
            "strategy_explicit": strategy_explicit,
            "ratio": ratio,
            "ratio_explicit": ratio_explicit,
        }
```

## 二、快捷标签 + 自然语言

### 2.1 处理流程

```
用户选择快捷标签 → 前端构建参数文本 → [用户已选择参数：功能=横竖屏转换，目标方向=竖屏 9:16，转换策略=填充黑边]
                 ↓
后端接收 → analyze_intent() → _parse_ui_params() [匹配！]
         → 直接设置状态（不经过 LLM）
         → 执行相应功能
```

### 2.2 核心代码文件

#### 2.2.1 前端参数格式化：`frontend/src/stores/app.ts`

**方法**：`formatSelectedParams() -> string`

**用途**：将 UI 选择的状态格式化为发送给后端的参数字符串

**核心代码**（第 131-180 行）：
```typescript
function formatSelectedParams(): string {
  const parts: string[] = [];

  if (currentFeature.value) {
    // 功能类型
    const featureMap = {
      'orient': '横竖屏转换',
      'compress': '视频压缩',
      'trim': '视频修剪',
      ...
    };
    parts.push(`功能=${featureMap[currentFeature.value]}`);

    // 横竖屏转换的参数
    if (currentFeature.value === 'orient') {
      if (selectedOrientation.value) {
        const ratioText = selectedRatio.value || '';
        parts.push(`目标方向=${selectedOrientation.value === 'portrait' ? '竖屏' : '横屏'} ${ratioText}`);
      }
      if (selectedStrategy.value) {
        const strategyMap = {
          'pad': '填充黑边',
          'crop': '中心裁剪',
          'smart_crop': '智能裁剪',
          'stretch': '拉伸填充',
        };
        parts.push(`转换策略=${strategyMap[selectedStrategy.value]}`);
      }
    }
    ...
  }

  if (parts.length === 0) return '';
  return `[用户已选择参数：${parts.join('，')}]`;
}
```

#### 2.2.2 后端参数解析：`backend/agent/nodes/analyze.py`

**方法**：`_parse_ui_params(user_input: str) -> dict`

**用途**：解析前端发送的参数字符串

**前置代码**：由 `analyze_intent()` 第 199 行调用
```python
ui_params = _parse_ui_params(user_input)
if ui_params.get("found"):
    # 进入快捷标签处理路径
    ...
    return state
```

**核心代码**（第 94-187 行）：
```python
def _parse_ui_params(user_input: str) -> dict:
    result = {"found": False}

    # 检查是否包含 UI 参数格式
    if "[用户已选择参数：" not in user_input:
        return result

    # 解析功能类型
    feature_match = re.search(r'功能\s*=\s*([^，,\]]+)', user_input)
    if feature_match:
        feature_text = feature_match.group(1).strip()
        feature_map = {
            "横竖屏转换": "convert",
            "视频压缩": "compress",
            ...
        }
        for name, feat in feature_map.items():
            if name in feature_text:
                result["feature"] = feat
                result["found"] = True
                break

    # 解析目标方向
    orient_match = re.search(r'目标方向\s*=\s*([^，,\]]+)', user_input)
    if orient_match:
        orient_text = orient_match.group(1).strip()
        if "竖屏" in orient_text:
            result["target_orientation"] = "portrait"
        elif "横屏" in orient_text:
            result["target_orientation"] = "landscape"

        # 解析比例
        ratio_map = {"9:16": 0.5625, "4:5": 0.8, "16:9": 1.7778, ...}
        for ratio_text, ratio_value in ratio_map.items():
            if ratio_text in orient_text:
                result["target_ratio"] = ratio_value
                break

    # 解析转换策略
    strategy_match = re.search(r'转换策略\s*=\s*([^，,\]]+)', user_input)
    if strategy_match:
        strategy_text = strategy_match.group(1).strip()
        strategy_map = {
            "填充黑边": "pad",
            "中心裁剪": "crop",
            "智能裁剪": "smart_crop",
            ...
        }
        for name, strategy in strategy_map.items():
            if name in strategy_text:
                result["strategy"] = strategy
                result["strategy_text"] = name
                break

    return result
```

## 三、两种方案差异对比

### 3.1 流程差异

| 步骤 | 纯自然语言 | 快捷标签 |
|------|-----------|----------|
| 1. UI 参数解析 | `_parse_ui_params()` 返回 `found=False` | `_parse_ui_params()` 返回 `found=True` |
| 2. LLM 解析 | **参与**（可能失败） | **跳过** |
| 3. 本地解析 | **参与**（作为 LLM 降级） | **跳过** |
| 4. 参数来源 | LLM + 本地关键词 | 前端发送的固定格式 |
| 5. 处理速度 | 较慢（需 LLM 调用） | 快速（直接解析） |
| 6. 参数修订 | 需检测明确提及的参数 | 直接覆盖旧值 |

### 3.2 代码执行路径差异

```
                    ┌─────────────────────────────────────┐
                    │        analyze_intent(state)         │
                    └─────────────────────────────────────┘
                                      │
                    ┌─────────────────┴─────────────────┐
                    ▼                                   ▼
        ┌───────────────────┐               ┌───────────────────┐
        │ _parse_ui_params()│               │ _parse_ui_params()│
        │ found = True      │               │ found = False     │
        └───────────────────┘               └───────────────────┘
                    │                                   │
                    ▼                                   ▼
        ┌───────────────────┐               ┌───────────────────┐
        │ 直接设置状态       │               │ LLM 解析           │
        │ 无需 LLM          │               │ parse_intent()    │
        └───────────────────┘               └───────────────────┘
                    │                                   │
                    ▼                                   ▼
        ┌───────────────────┐               ┌───────────────────┐
        │ IntentParser.parse│               │ 本地解析降级       │
        │ (不参与)          │               │ (LLM 失败时)      │
        └───────────────────┘               └───────────────────┘
```

### 3.3 状态更新逻辑差异

| 场景 | 纯自然语言 | 快捷标签 |
|------|-----------|----------|
| 参数首次设置 | `if local_parsed.get("strategy_explicit"):` | `state["strategy"] = strategy` 直接赋值 |
| 参数修订 | 检测 `*_explicit` 标志，覆盖旧值 | 直接覆盖旧值 |
| 多轮对话参数保留 | 可能被旧值阻塞（已修复） | 每次都发送完整参数 |

## 四、Claude Code 开发提示词

当需要添加新技能或修改现有技能时，使用以下提示词模板：

### 4.1 添加新技能模板

```
请为 [技能名称] 添加支持，需要实现：

1. **快捷标签参数格式**
   - 功能名称：[技能中文名]
   - 参数格式：`[用户已选择参数：功能=[技能中文名]，[参数1]=[值1]，[参数2]=[值2]]`

2. **前端修改** (`frontend/src/stores/app.ts`)
   - 在 `formatSelectedParams()` 中添加技能判断
   - 在 `featureMap` 中添加映射
   - 添加参数解析逻辑

3. **后端修改** (`backend/agent/nodes/analyze.py`)
   - 在 `_parse_ui_params()` 的 `feature_map` 中添加技能名映射
   - 添加参数解析正则表达式
   - 在 `analyze_intent()` 中添加 `elif feature == "[技能英文名]":` 分支
   - 设置对应状态字段

4. **执行节点** (`backend/agent/nodes/execute.py` 或新建)
   - 创建 `execute_[技能名](state)` 函数
   - 实现业务逻辑

5. **自然语言解析** (`backend/agent/prompts.py`)
   - 在 `TOOL_RECOGNITION_PROMPT` 中添加关键词映射
   - 在对应工具的 `*_PARAM_PROMPT` 中添加示例

6. **本地关键词解析** (`backend/agent/nodes/analyze.py`)
   - 在 `IntentParser` 中添加关键词
   - 在 `parse()` 方法中添加解析逻辑

7. **测试验证**
   - 快捷标签路径：选择标签 → 检查参数正确传递
   - 自然语言路径：输入 → 检查 LLM 解析和本地解析降级
   - 多轮修订：首次设置 → 修订参数 → 检查新值生效
```

### 4.2 修复参数修订问题模板

```
当用户通过自然语言修订已给参数时，需要：

1. **确保本地解析能识别修订意图**
   - 在 `IntentParser.STRATEGY_KEYWORDS` 等字典中添加修订相关关键词
   - 如：["改为", "改成", "换成", "换为", "修改为"]

2. **确保状态正确更新**
   - 修改 `analyze_intent()` 中的参数合并逻辑
   - 从 `if local_parsed.get("strategy") and not strategy:` 改为
   - `if local_parsed.get("strategy_explicit"):`
   - 原因：当用户明确提到策略时，应覆盖旧值而不是保留

3. **生成正确的回复**
   - 当检测到参数修订时，回复应体现修订内容
   - 如："好的，已将策略改为智能裁剪"
```

### 4.3 确保参数完整性模板

```
LLM 解析参数可能不完整，需要：

1. **本地关键词解析作为降级**
   ```python
   local_parsed = IntentParser.parse(user_input)
   if local_parsed.get("strategy_explicit"):
       strategy = local_parsed["strategy"]
   ```

2. **生成完整回复**
   ```python
   if all_params_provided and (local_parsed.get("orientation") or ...):
       orientation_str = "竖屏" if target_orientation == "portrait" else "横屏"
       ratio_str = "9:16" if ratio and ratio < 1 else "16:9"
       strategy_str = {"pad": "填充黑边", ...}.get(strategy, strategy)
       llm_response = f"好的，使用{ratio_str}{orientation_str}和{strategy_str}策略..."
   ```

3. **避免逐条提问**
   - 确保 `all_params_provided = orientation_explicit and strategy_explicit`
   - 只有参数完整时才进入执行，否则让用户一次性补充所有缺失参数
```

## 五、常见问题与解决方案

### 5.1 问题：LLM 返回通用欢迎语而不是解析参数

**原因**：LLM 没有遵循示例格式

**解决**：使用本地关键词解析作为降级（已在代码中实现）

### 5.2 问题：多轮对话中修订参数不生效

**原因**：`if local_parsed.get("strategy") and not strategy` 检查阻止覆盖

**解决**：改为 `if local_parsed.get("strategy_explicit"):` 直接覆盖

### 5.3 问题：快捷标签参数未正确传递

**原因**：`formatSelectedParams()` 返回空字符串

**解决**：确保前端正确格式化参数，参考第 2.2.1 节代码

### 5.4 问题：参数缺失时逐条提问

**原因**：`all_params_provided` 判断逻辑问题

**解决**：一次性告知所有缺失参数，而不是逐个提问
