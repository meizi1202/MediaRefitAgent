# 「添加字幕」场景设计方案

> 更新时间：2026-09-04
> 状态：✅ 已完成实现

---

## 方案总结

今天共探索了 **4 种剪映草稿访问方案**，各方案存在问题如下：

| 方案 | 描述 | 状态 | 存在问题 |
|------|------|------|----------|
| **方案一：本地模式** | 草稿保存在本地目录，用户在剪映中手动打开 | ✅ 可用 | 1. 字幕位置在窗口底部不生效<br>2. 字体设置不生效<br>3. 需要手动在剪映中导入草稿 |
| **方案二：OSS + 中转服务** | 草稿上传到 OSS，搭建中转服务 API | ✅ 技术可行 | 1. CapcutMate 客户端期望**加密**的草稿 JSON<br>2. Coze 返回的是加密内容，我们返回的是明文<br>3. 剪映小助手解密失败 |
| **方案三：OSS 直接访问** | 草稿上传到 OSS，返回 OSS URL | ❌ 不可行 | 1. OSS URL 指向**目录**，不是文件<br>2. 剪映小助手无法直接解析目录<br>3. 需要目录索引 API |
| **方案四：本地隧道** | 使用 localtunnel/cloudflared/ngrok 打通本地服务 | ❌ 不可行 | 1. localtunnel 频繁断开，不稳定<br>2. cloudflared 免费版限速（429 错误）<br>3. ngrok 需要注册账号 |

---

### 方案一详细问题分析

**字幕问题：**
1. **位置问题**：字幕显示在窗口底部，但可能不是预期位置
   - 尝试通过 `transform_y=-0.8` 调整位置
2. **字体问题**：设置的字体未生效
   - 需要使用 `FontType` 枚举而非字符串

**推荐配置：**
```python
# 字幕样式
text_style = TextStyle(
    size=10,           # 字号
    color=(1,1,1),     # 白色
    auto_wrapping=True, # 自动换行
    align=1,           # 居中对齐
    max_line_width=0.9
)
# 位置设置
clip_settings = ClipSettings(transform_y=-0.8)
# 字体设置
font = FontType.新青年体
```

---

### 方案二关键发现

Coze 的中转服务返回的草稿内容是**加密的**：
```
C4VECtbx3/hg2ejTHm8sylxR/LK2WeWySGxTSm465PoimnjiAvwQpHHAMkNAJkbu1lzI6...
```

而我们上传的是**明文 JSON**：
```
{"canvas_config":{"width":1920,"height":1080},...}
```

CapcutMate 客户端尝试用 CBC 模式解密明文，导致错误：
```
Data must be padded to 16 byte boundary in CBC mode
```

**解决方向**：需要研究 capcut-mate 的加密逻辑，模拟 Coze 的加密流程。

---

## 最终实施方案

鉴于方案二需要深入研究加密逻辑，建议采用**方案一（本地模式）+ 手动导入**作为当前方案：

1. 草稿保存在 `JIANYING_DRAFT_DIR` 目录
2. 用户在剪映中通过「导入草稿」功能打开
3. 字幕样式通过配置生效（字号 10、自动换行、居中对齐、底部位置）

## Context

在"剪映对接"功能下新增"添加字幕"子场景，支持两种交互方式：

### 方式一：快捷标签方式
1. 点击"剪映对接"标签
2. 配置字幕样式（字体、颜色、字号）
3. 上传视频文件
4. 输入"帮我添加字幕"
5. Agent 自动执行 Whisper 识别 -> 创建草稿 -> 添加字幕
6. 展示 draft_url

### 方式二：纯自然语言方式
1. 直接输入："帮我把视频添加到剪映并生成字幕"
2. Agent 自动识别意图并执行完整流程
3. 返回 draft_url

**字体样式来源**：
- 方式一（标签）：用户配置的字幕样式
- 方式二（自然语言）：解析用户消息中的样式关键词（如"白色字体"），无则使用默认值（白色 #FFFFFF、字号 10、新青年体）
