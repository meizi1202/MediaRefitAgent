# 老视频修复技能 - 需求文档

## 1. 概述

### 1.1 背景
随着视频资料数字化进程加速，大量珍贵的老视频、胶片电影、历史影像需要修复和增强。这些老视频普遍存在噪点、模糊、褪色、划痕、闪烁等问题。

### 1.2 目标
在 MediaRefitAgent 视频编辑智能体中添加"老视频修复"技能，支持通过自然语言指令对老旧视频进行专业级修复和增强。

### 1.3 范围
本技能涵盖以下修复类别：
| 类别 | 功能 |
|------|------|
| 基础修复 | 去噪、去抖动、色彩修复、对比度增强 |
| 胶片修复 | 划痕修复、闪烁修复 |
| 增强升级 | 补帧（提升流畅度）、超分辨率（提升清晰度） |

### 1.4 功能与模型总览

#### 1.4.1 功能清单

| 序号 | 功能 | 功能说明 | 技术方案 | AI模型 |
|------|------|----------|----------|--------|
| 1 | 去噪 | 去除雪花点、颗粒感、随机噪点 | FFmpeg hqdn3d/nlmeans | DnCNN |
| 2 | 去抖动 | 修复相机抖动、运动模糊 | FFmpeg unsharp + convolution | - |
| 3 | 色彩修复 | 修复褪色、偏色、增强饱和度 | FFmpeg eq/colorbalance | - |
| 4 | 对比度增强 | 提升暗部亮部分辨度 | FFmpeg eq/histeq | - |
| 5 | 划痕修复 | 去除老胶片划痕、条纹 | FFmpeg descratch + 帧间插值 | - |
| 6 | 闪烁修复 | 修复画面亮度不均、闪烁 | FFmpeg fade + 亮度平滑 | - |
| 7 | 补帧 | 插入中间帧、提升流畅度 | FFmpeg minterpolate | RIFE |
| 8 | 超分辨率 | 放大分辨率、提升清晰度 | FFmpeg scale + lanczos | Real-ESRGAN |

** 补充备注: **
- FFmpeg 原生滤镜仅为传统算法，**划痕、抖动原生能力效果有限，生产级需接入对应 AI 模型**；FFmpeg 只做编解码、管道调度。
- minterpolate 是 FFmpeg 传统补帧，RIFE 为 AI 补帧模型，工程上一般 FFmpeg 对接 RIFE 推理输出。
- scale+lanczos 只是普通插值放大，不能实现 AI 超分；Real‑ESRGAN 负责 AI 超分推理，FFmpeg 负责帧输入输出与编码封装。

#### 1.4.2 模型使用说明

**FFmpeg 滤镜（基础功能，无额外依赖）**
- `hqdn3d` / `nlmeans` - 去噪
- `unsharp` / `convolution` - 锐化
- `eq` / `colorbalance` / `curves` - 色彩/对比度
- `descratch` - 划痕修复
- `fade` / `negate` - 闪烁修复
- `minterpolate` - 基础补帧
- `scale` - 基础缩放

**AI 模型（可选，需要安装）**

| 模型 | 用途 | 模型大小 | 下载方式 |
|------|------|----------|----------|
| DnCNN | AI去噪 | ~50MB | 首次使用时自动下载 |
| RIFE | AI补帧 | ~400MB | 首次使用时自动下载 |
| Real-ESRGAN | AI超分辨率 | ~65MB | 首次使用时自动下载 |

#### AI 模型详细说明

##### 1. DnCNN（AI去噪）

| 项目 | 内容 |
|------|------|
| **ModelScope 模型** | 预训练权重 `damo/cv_denoise_pidinet`（需确认完整推理管线） |
| **GitHub 官方** | https://github.com/cszn/DnCNN |
| **预训练权重** | 首次使用时自动下载，或从 CSDN/百度网盘手动下载 |
| **模型大小** | ~50MB |
| **推荐理由** | DnCNN 是最经典的深度学习去噪模型之一，采用残差学习和批量归一化技术，可处理未知噪声水平的盲去噪，轻量高效。**注意**：`cv_denoise_pidinet` 为预训练权重，完整推理需自行封装。 |

##### 2. RIFE（AI补帧）

| 项目 | 内容 |
|------|------|
| **ModelScope 模型** | `Damo_XR_Lab/cv_rife_video-frame-interpolation` |
| **GitHub 官方** | https://github.com/hzwer/Practical-RIFE |
| **推荐版本** | v4.25（默认版）/ v4.24+（适合 AI 生成视频后处理） |
| **模型大小** | ~400MB |
| **推荐理由** | ECCV 2022 论文算法，实时中间流估计（IFNet），支持 720p@30fps 实时插帧，比传统光流方法快 3-5 倍，插帧质量高 |

##### 3. RealBasicVSR（AI超分辨率/视频超分）

| 项目 | 内容 |
|------|------|
| **ModelScope 模型** | `damo/cv_realbasicvsr_video-super-resolution_videolq` |
| **论文** | CVPR 2022 - Investigating Tradeoffs in Real-World Video Super-Resolution |
| **GitHub 官方** | https://github.com/ckkelvinchan/RealBasicVSR |
| **模型大小** | ~65MB |
| **推荐理由** | 达摩院官方上架，专门针对真实低质视频（老录像 / VHS）超分，支持盲超分无需预知退化类型，比 Real-ESRGAN 更适合老视频修复场景 |

#### 1.4.3 硬件资源诉求

## 2. 功能详细说明

### 2.1 基础修复

#### 2.1.1 去噪（Denoise）
- **功能描述**：去除视频中的雪花点、颗粒感和随机噪点
- **技术方案**：FFmpeg `nlmeans` 或 `hqdn3d` 滤镜
- **参数选项**：
  - 强度等级：轻度 / 中度 / 强力
  - 时间半径：1-7（nlmeans）
  - 空间半径：1-7（nlmeans）
- **使用场景**："去除视频噪点"、"修复老电影的颗粒感"

#### 2.1.2 去抖动（Deblur）
- **功能描述**：修复因相机抖动或运动模糊导致的画面模糊
- **技术方案**：FFmpeg `dejudder` 或锐化增强（`unsharp` + `convolution`）
- **参数选项**：
  - 模糊类型：运动模糊 / 离焦模糊
  - 锐化强度：低 / 中 / 高
- **使用场景**："修复模糊的视频"、"让画面更清晰"

#### 2.1.3 色彩修复（Color Correction）
- **功能描述**：修复褪色视频的色彩，增强饱和度和色彩还原
- **技术方案**：FFmpeg `eq` / `colorbalance` / `colortemperature` 滤镜组合
- **参数选项**：
  - 饱和度：-100 ~ +100
  - 对比度：-100 ~ +100
  - 色温：暖色 / 正常 / 冷色
  - 色彩校正模式：自动 / 手动
- **使用场景**："修复褪色的老电影"、"增强色彩"

#### 2.1.4 对比度增强（Contrast Enhancement）
- **功能描述**：提升画面暗部和亮部的区分度，改善视觉效果
- **技术方案**：FFmpeg `contrast` / `histeq` / `adaptive_threshold`
- **参数选项**：
  - 对比度级别：低 / 中 / 高 / 自适应
- **使用场景**："提高对比度"、"让画面更有层次"

---

### 2.2 胶片修复

#### 2.2.1 划痕修复（Scratch Removal）
- **功能描述**：去除老胶片上的划痕、条纹和斑块
- **技术方案**：FFmpeg `removeburnin` + 帧间插值修复
- **参数选项**：
  - 修复强度：轻度 / 中度 / 强力
  - 检测阈值：自动 / 手动
- **使用场景**："修复老胶片划痕"、"去除划痕"

#### 2.2.2 闪烁修复（Flicker Removal）
- **功能描述**：修复老电影画面亮度不均匀、闪烁问题
- **技术方案**：FFmpeg `fade` / `negate` + 帧间亮度平滑
- **参数选项**：
  - 闪烁类型：亮度闪烁 / 颜色闪烁
  - 平滑强度：低 / 中 / 高
- **使用场景**："修复画面闪烁"、"让老电影播放更平滑"

---

### 2.3 增强升级

#### 2.3.1 补帧（Frame Interpolation）
- **功能描述**：在原视频帧之间插入中间帧，提升视频流畅度
- **技术方案**：
  - 基础：FFmpeg `minterpolate`（帧率倍增）
  - 高级：RIFE 或 similar AI 模型（高质量插帧）
- **参数选项**：
  - 输出帧率：24fps / 30fps / 60fps / 自定义
  - 插帧模式：基础（FFmpeg）/ AI增强（RIFE）
- **使用场景**："让老视频更流畅"、"补帧到60fps"

#### 2.3.2 超分辨率（Super Resolution）
- **功能描述**：提升视频分辨率和清晰度，支持放大而不失真
- **技术方案**：
  - 基础：FFmpeg `scale` + lanczos/spline 缩放
  - AI增强：Real-ESRGAN 或 similar 模型
- **参数选项**：
  - 放大倍数：2x / 4x / 自定义
  - 模式：基础（ lanczos）/ AI增强
  - 输出分辨率：720p / 1080p / 4K / 自定义
- **使用场景**："提升视频清晰度"、"放大到4K"

### 3.3 FFmpeg 滤镜方案

| 功能 | 滤镜 | 说明 |
|------|------|------|
| 去噪 | `hqdn3d` 或 `nlmeans` | hqdn3d 更快，nlmeans 质量更好 |

| 对比度 | `eq=contrast=1.5` | 对比度调整 |

| 补帧 | `minterpolate=fps=60` | 基础帧率插值 |
| 超分辨率 | `scale=1920:1080:flags=lanczos` | 基础缩放 |

### 3.5 AI 去噪模块（详细设计）

#### 3.5.1 技术方案对比

| 方案 | 模型 | 优点 | 缺点 | 推荐场景 |
|------|------|------|------|----------|
| DnCNN | DnCNN | 轻量、快速、效果好 | 仅支持图像 | 离线预处理 |
| BasicSR | EDSR/RCAN | 开源成熟、支持图像和视频 | 需预训练模型 | 通用场景 |
| BM3D | 传统+深度 | 效果好、保边能力强 | 速度慢 | 高质量需求 |

#### 3.5.2 推荐方案：基于 DnCNN 的视频去噪

**模型来源**：使用预训练的 DnCNN 模型（VGG 风格）

**实现流程**：
```
输入视频 → 帧提取 → 分批处理 → DnCNN 去噪 → 帧合成 → 输出视频
                    ↓
              进度回调（每批更新）
```

**核心参数**：
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `denoise_strength` | float | 15.0 | 去噪强度 (1-50) |
| `batch_size` | int | 8 | 批处理大小 |
| `gpu_enabled` | bool | auto | 是否使用GPU |
| `tile_size` | int | 256 | 分块处理大小（防显存溢出） |

**输入输出规范**：
```python
# 输入
input_path: str  # 视频文件路径，支持 mp4/avi/mov

# 输出
output_path: str  # 去噪后视频路径

# 返回
{
    "success": bool,
    "output_file": str,
    "frames_processed": int,
    "processing_time": float,
    "avg_fps": float
}
```

**依赖要求**：
```txt
torch >= 1.9.0          # PyTorch 深度学习框架
torchvision >= 0.10.0   # 预训练模型加载
opencv-python >= 4.5.0  # 视频读写
```

**模型下载**：
```python
# 首次使用时自动下载 (~50MB)
MODEL_URL = "https://download.pytorch.org/models/dncnn_pytorch.tar.gz"
```

#### 3.5.3 AI 去噪质量等级

| 等级 | 强度值 | 适用场景 | 处理速度 |
|------|--------|----------|----------|
| 轻度 | 5-10 | 轻微噪点、保留细节 | 快 |
| 中度 | 10-20 | 一般老视频 | 中等 |
| 强力 | 25-35 | 严重噪点、胶片颗粒 | 慢 |
| 极限 | 40-50 | 极高噪点 | 最慢 |

#### 3.5.4 20MB 视频处理时长估算

**假设**：20MB 1080p H.264 视频 ≈ 50-60 秒，1500-1800 帧 @ 30fps

| 硬件配置 | 每帧速度 | 总帧数 | 预估时长（含I/O） |
|----------|---------|--------|------------------|
| RTX 3070+ | ~120 fps | ~1500帧 | **1-2 分钟** |
| GTX 1080 / RTX 2060 | ~60 fps | ~1500帧 | **3-4 分钟** |
| GTX 1060 / 1650 | ~30 fps | ~1500帧 | **6-8 分钟** |
| 现代笔记本 (MX450) | ~15 fps | ~1500帧 | **12-15 分钟** |
| CPU (i7 8线程) | ~8 fps | ~1500帧 | **8-12 分钟** |
| 普通 CPU | ~3 fps | ~1500帧 | **15-25 分钟** |

**加速建议**：
- 使用 GPU（速度提升 10-20x）
- 降低 `tile_size` 减少显存占用（略微影响速度）
- 使用 Lite 模型（速度提升 2x，质量略降）

### 3.6 AI 补帧模块（详细设计）

#### 3.6.1 技术方案对比

| 方案 | 算法 | 优点 | 缺点 | 推荐场景 |
|------|------|------|------|----------|
| FFmpeg minterpolate | 运动搜索 | 无需额外依赖 | 质量一般 | 快速预览 |
| RIFE | 光流 + 锐化 | 速度快、质量好、开源 | 需GPU | 生产环境首选 |
| SuperSloMo | 光流插值 | 质量最高 | 速度慢 | 最高质量需求 |
| AdaCoffin | 帧混合 | 简单 | 质量差 | 备选方案 |

#### 3.6.2 推荐方案：基于 RIFE 的实时补帧

**项目来源**：https://github.com/hzwer/Practical-RIFE

**实现流程**：
```
输入视频 → 帧提取 → 光流计算 → 中间帧生成 → 帧合成 → 输出视频
              ↓
        双向光流 + 特征融合
```

**核心参数**：
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `target_fps` | int | 60 | 目标帧率 |
| `interpolation_factor` | int | 2 | 插帧倍数 (2=翻倍, 4=4倍) |
| `img_format` | str | "jpg" | 中间帧格式 |
| `gpu_enabled` | bool | auto | 是否使用GPU |
| `scale` | float | 1.0 | 输入缩放 (0.5=加速) |

**输入输出规范**：
```python
# 输入
input_path: str           # 视频文件路径
target_fps: int = 60      # 目标帧率
return_frames: bool = False  # 是否返回中间帧列表

# 输出
output_path: str  # 补帧后视频路径

# 返回
{
    "success": bool,
    "output_file": str,
    "input_fps": float,
    "output_fps": float,
    "frames_generated": int,
    "processing_time": float
}
```

**RIFE 模型变体**：
| 模型 | 精度 | 速度 | 显存需求 |
|------|------|------|----------|
| RIFE-Lite | 低 | 最快 | 2GB |
| RIFE (TFLite) | 中 | 快 | 2GB |
| RIFE (FP32) | 高 | 中 | 4GB |
| RIFE (FP16) | 高 | 快 | 4GB |

**依赖要求**：
```txt
torch >= 1.9.0              # PyTorch 框架
```

#### 3.6.3 补帧质量配置

| 模式 | 目标帧率 | 插帧倍数 | 适用场景 | 处理速度 |
|------|----------|----------|----------|----------|
| 流畅 | 30fps | 2x | 24fps→30fps | 快 |
| 高帧率 | 60fps | 2-3x | 24/30fps→60fps | 中 |
| 超流畅 | 120fps | 4-5x | 任何帧率 | 慢 |
| 电影级 | 自定义 | 自适应 | 24fps经典电影 | 取决于目标 |

#### 3.6.4 补帧与编码质量

| 原视频帧率 | 目标帧率 | 编码建议 | 说明 |
|------------|----------|----------|------|
| 24fps | 48fps | H.264 CRF 18 | 2x插帧后编码 |
| 24fps | 60fps | H.265 CRF 22 | 2.5x，质量优先 |
| 30fps | 60fps | H.264 CRF 20 | 2x插帧 |
| 30fps | 120fps | H.265 CRF 23 | 4x插帧，文件较大 |

#### 3.6.5 注意事项

**场景限制**：
- 闪烁/频闪视频：插帧会放大闪烁效果，需先进行闪烁修复
- 字幕/台标：会产生重影，建议先去除
- 镜头剧烈切换：会产生错误插帧，需场景检测

**质量建议**：
- 24fps 电影 → 48fps (2x) 最佳
- 30fps 视频 → 60fps (2x) 最佳
- 不要超过原始分辨率的 4 倍插帧

## 4. API 接口设计

### 4.1 新增端点

#### POST `/api/restore`
**功能**：老视频修复（同步）
```
请求：
{
  "file": File,
  "preset": "basic" | "film" | "enhanced" | "custom",
  "options": {
    "denoise": { "enabled": true, "level": "medium" },
    "deblur": { "enabled": true, "level": "low" },
    "color_correct": { "enabled": true, "saturation": 10 },
    "contrast": { "enabled": true, "level": "medium" },
    "scratch_remove": { "enabled": true, "level": "medium" },
    "flicker_remove": { "enabled": true, "level": "low" },
    "interpolate": { "enabled": false, "fps": 60 },
    "super_resolution": { "enabled": false, "scale": 2 }
  }
}

响应：
{
  "task_id": "xxx",
  "status": "completed",
  "output_file": "/outputs/xxx_restored.mp4",
  "processing_time": 120.5
}
```

#### POST `/api/restore-stream`
**功能**：老视频修复（SSE 流式）
```
事件流：
{"event": "start", "progress": 0.0, "message": "开始修复..."}
{"event": "progress", "progress": 0.25, "message": "去噪处理中...", "stage": "denoise"}
{"event": "progress", "progress": 0.50, "message": "色彩修复中...", "stage": "color_correct"}
{"event": "progress", "progress": 0.75, "message": "增强处理中...", "stage": "enhance"}
{"event": "complete", "progress": 1.0, "message": "修复完成", "output_file": "xxx.mp4"}
```

#### GET `/api/capabilities`
**[修改]** 在现有响应中添加老视频修复相关能力：
```json
{
  "restoration": {
    "supported": true,
    "presets": ["basic", "film", "enhanced"],
    "features": {
      "denoise": true,
      "deblur": true,
      "color_correction": true,
      "contrast_enhancement": true,
      "scratch_removal": true,
      "flicker_removal": true,
      "frame_interpolation": true,
      "super_resolution": true
    },
    "ai_enhanced": {
      "denoise": false,
      "interpolate": false,
      "super_resolution": false
    }
  }
}
```

## 10. 剪映对接方案分析

### 10.1 剪映官方 API 现状

**结论：剪映没有官方公开 API**

经过调研，剪映（CapCut海外版）目前：
- ❌ **无官方公开 API**：字节跳动官方未提供任何形式的 API 接口
- ❌ **无开放平台**：无阿里云/腾讯云形式的开放能力平台
- ❌ **无 SDK**：未提供任何官方开发工具包

### 10.2 第三方方案：JianYingApi

虽然存在开源社区开发的第三方方案，但存在明显局限：

**项目地址**：https://github.com/kokojacket/JianYingApi

| 维度 | 说明 |
|------|------|
| 技术原理 | 通过Hook剪映本地进程实现能力调用 |
| 实现方式 | 需要在本地运行剪映客户端 |
| 依赖要求 | 剪映桌面版必须安装并运行 |
| 稳定性 | 非官方支持，可能因剪映版本更新失效 |
| 适用场景 | 桌面自动化、研究目的 |

**局限性**：
1. **需要安装剪映**：无法在服务器/云端部署
2. **平台限制**：仅支持 Windows/macOS 桌面端
3. **不稳定**：依赖进程Hook，剪映更新后可能失效
4. **无远程调用**：不支持 API 形式的远程调用
5. **法律风险**：可能违反剪映使用协议

### 10.3 方案对比

| 方案 | 自研 FFmpeg | 自研 AI 模型 | JianYingApi 第三方 |
|------|-------------|--------------|-------------------|
| **部署方式** | 服务器/云端均可 | 服务器/云端均可 | 必须本地桌面 |
| **API 化** | ✅ 完整支持 | ✅ 完整支持 | ❌ 不支持 |
| **稳定性** | ✅ 高 | ✅ 高 | ⚠️ 依赖剪映版本 |
| **维护成本** | 低 | 中 | 高（易失效） |
| **视频修复能力** | 基础到中等 | 中到高级 | 取决于剪映能力 |
| **成本** | GPU 资源 | GPU + 模型 | 剪映免费 |
| **可定制性** | ✅ 完全可控 | ✅ 完全可控 | ❌ 受限于剪映 |

### 10.4 结论与建议

**不推荐对接剪映 API**，原因如下：

1. **无官方 API**：无法进行正规集成
2. **架构不匹配**：MediaRefitAgent 是 API 服务，剪映是桌面应用
3. **不稳定**：第三方方案依赖版本更新，无法保障服务稳定性
4. **部署限制**：无法在服务器环境运行剪映

**建议方案**：

| 场景 | 推荐方案 |
|------|----------|
| 基础修复 | FFmpeg 滤镜（已覆盖） |
| 中级修复 | FFmpeg + AI 去噪（DnCNN） |
| 高级修复 | FFmpeg + AI 补帧（RIFE）+ 超分（ESRGAN） |
| 专业级 | 商业视频处理服务（如达芬奇、Adobe Premiere API） |
