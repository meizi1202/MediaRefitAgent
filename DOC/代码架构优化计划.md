# MediaRefitAgent 代码架构优化计划

## Context

用户反馈代码架构需要优化，最关注**模块解耦**。当前架构存在严重耦合问题：

1. **Agent/Video 无抽象层** - 直接函数调用，缺乏接口抽象
2. **API 层臃肿** - `api/fastapi_app.py` 2500+ 行，职责过多
3. **FFmpeg 路径硬编码** - `video/processor.py` 和 `video/funclip_wrapper.py` 各有一份
4. **策略字符串硬编码** - 散落各处如 `"execute_transform"`

## 问题分析

### 耦合度量化（7/10 高度耦合）

| 问题 | 程度 | 说明 |
|------|------|------|
| 直接函数调用 | 高 | agent/api 直接 import video 具体函数 |
| 无抽象层 | 高 | 没有 Protocol/ABC 接口 |
| FFmpeg 路径硬编码 | 中 | 两处重复硬编码 |
| 策略硬编码 | 中 | 字符串字面量散落 |

### 关键发现

1. **agent 调用 video**：
   - `video_agent.py` 直接 import `video.processor.compress_video`, `trim_video` 等
   - 无中介层，直接深度耦合

2. **API 调用 video**：
   - `api/fastapi_app.py` 直接 import 多个 video 模块函数

3. **数据传递**：
   - 使用 dataclass DTO (TransformRequest, TransformResult)
   - 但 DTO 定义在 video 模块，agent 直接依赖

## 推荐方案

### 核心原则

**渐进式重构，引入 Protocol 接口 + 依赖注入**

### Phase 1: 统一配置管理

**目标**：消除硬编码配置

**新增** `services/config.py`：
```python
from dataclasses import dataclass
import os
from dotenv import load_dotenv

load_dotenv()

@dataclass
class Config:
    # FFmpeg
    FFMPEG_DIR: str = os.getenv("FFMPEG_DIR", "C:/ffmpeg/ffmpeg-9.0-essentials_build/bin")
    FFMPEG_PATH: str = os.path.join(FFMPEG_DIR, "ffmpeg.exe")
    FFPROBE_PATH: str = os.path.join(FFMPEG_DIR, "ffprobe.exe")
    OUTPUT_DIR: str = os.getenv("OUTPUT_DIR", "F:/video")
    # MiniMax
    MINIMAX_API_KEY: str = os.getenv("MINIMAX_API_KEY", "")
    MINIMAX_API_URL: str = os.getenv("MINIMAX_API_URL", "https://api.minimax.chat/v1/text/chatcompletion_v2")
    MINIMAX_MODEL: str = os.getenv("MINIMAX_MODEL_NAME", "MiniMax-M2.7")
    # 默认值
    DEFAULT_STRATEGY: str = os.getenv("DEFAULT_STRATEGY", "pad")
    DEFAULT_TARGET_RATIO: float = float(os.getenv("DEFAULT_TARGET_RATIO", "0.5625"))
    WHISPER_MODEL: str = os.getenv("WHISPER_MODEL", "base")
```

**修改**：
- `video/processor.py` - 从 `services/config.py` 读取 FFmpeg 配置
- `video/funclip_wrapper.py` - 同上
- `agent/langchain_agent.py` - 从 `services/config.py` 读取 MiniMax 配置

### Phase 2: 引入 Protocol 接口层

**目标**：解耦 agent/api 与 video 实现

**新增** `agent/interfaces.py`：
```python
from typing import Protocol, Optional
from video.transformer import TransformRequest, TransformResult

class VideoProcessor(Protocol):
    """视频处理抽象接口"""
    def transform(self, request: TransformRequest) -> TransformResult: ...
    def compress(self, input_path: str, output_path: str, level: str, callback=None) -> bool: ...
    def trim(self, input_path: str, output_path: str, start: float, end: float, callback=None) -> bool: ...
    def concat(self, paths: list[str], output: str, keep_audio: bool, callback=None) -> bool: ...
    def get_metadata(self, path: str) -> VideoMetadata: ...
```

**Agent 使用依赖注入**：
```python
class VideoAgent:
    def __init__(self, processor: Optional[VideoProcessor] = None):
        self.processor = processor or DefaultVideoProcessor()
```

### Phase 3: 提取 Services 层（可选）

如果 API 层也需要解耦：

**新增目录** `services/`：
```
services/
    ├── __init__.py
    ├── video_service.py    # transform/compress/trim/concat
    └── editor_service.py   # 智能剪辑相关
```

**api/fastapi_app.py** 调用 service 而非直接调用 video 模块

## 实施顺序

1. **Phase 1**: 统一配置管理（低风险，独立验证）
2. **Phase 2**: Protocol 接口层（需修改 agent）
3. **Phase 3**: 可选，看项目复杂度需求

## 验证方法

1. 启动 API 服务
2. 测试横竖屏转换
3. 测试智能剪辑功能
4. 测试 Agent 多轮对话
5. 确认输出与重构前一致

## 风险评估

- Phase 1 风险低，配置外置不影响功能
- Phase 2 需谨慎，确保接口兼容
- 建议逐步提交，每阶段独立验证
