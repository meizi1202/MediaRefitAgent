# 电视台专家论坛短视频自动化生产需求文档

## 1. 背景与目标

### 1.1 台内现状

- **剪辑工具**：剪映桌面端（剪辑人员已熟练掌握）
- **已有资产**：固定片头片尾、台标水印、特定字体、字幕样式、标题卡片动画、固定转场、BGM 包装
- **剪辑人员诉求**：不希望更换剪辑软件，希望沿用现有视觉风格

### 1.2 业务痛点

| 痛点 | 说明 |
|------|------|
| 素材量大 | 一场论坛录制 2-3 小时原始视频 |
| 产出多样 | 需要高光集锦、专家观点切片、金句片段等多类型短视频 |
| 人工耗时长 | 找片段、切时间、套字幕、加转场、导出一整套流程人工操作 |
| 人力成本高 | 重复性剪辑工作占用专业人力 |

### 1.3 核心目标

**不换工具、不丢风格、批量自动化出片**

- 保留剪映现有包装样式（片头/片尾/台标/字幕/转场/BGM）
- 尽量减少人工逐段拖拽时间线
- 支持批量自动化产出多条短视频

#### 各模块技术范围与边界

| 模块 | 输入 | 输出 | 技术范围 | 边界（不做什么） |
|------|------|------|----------|------------------|
| **视频上传** | 原始视频文件 | 视频元数据、分片存储 | 视频格式校验、FFprobe 元数据读取、分片上传、断点续传 | 不做视频分析、不做剪辑 |
| **智能分析** | 视频文件 + 元数据 | 精彩片段列表、专家分割、金句候选 | 语音识别(Whisper)、YOLO 高光检测、场景分割、STT 时间戳对齐 | 不做视频剪辑、不做包装 |
| **批量剪辑** | 片段列表 + 剪辑任务 | 剪辑后的裸视频（无包装） | FFmpeg 片段提取、拼接、片段排序、时长控制 | 不加片头片尾、不烧字幕、不加水印 |
| **自动包装** | 裸视频 + 模板配置 | 最终成品视频 | 片头片尾注入、字幕烧录(Burn)、台标叠加、转场添加、BGM 混音 | 不识别内容、不切割片段 |

### 3.2 智能分析能力

#### 3.2.1 精彩片段识别
- 自动识别高光时刻（掌声、笑声、观点金句）
- 识别标准：画面能量、音频峰值、文本信息密度
- 输出：每个精彩片段的起止时间戳

#### 3.2.2 专家分割
- 自动识别不同专家的发言段落
- 按专家分组发言内容
- 支持指定专家（专家 A、专家 B）

#### 3.2.3 语音转文本（STT）
- 全量语音识别
- 时间戳对齐
- 支持关键词提取

#### 3.2.4 金句提取
- 自动识别观点鲜明、有传播力的语句
- 评分排序，提取 Top N 金句
- 每条金句时长控制在 15-30 秒

### 3.3 批量剪辑能力

#### 3.3.1 批量任务定义

#### 3.4.2 FFmpeg 能否完全复刻剪映效果？

**结论：大部分可复刻，存在差距需要人工补调**

| 效果类型 | FFmpeg 可复刻程度 | 说明 |
|----------|------------------|------|
| **片头/片尾** | ✅ 100% | 直接提取剪映导出的 MP4 文件，无损复用 |
| **台标水印** | ✅ 100% | FFmpeg overlay 完美实现 |
| **字幕样式** | ✅ 90% | 字体/颜色/背景/位置可复刻，ASS 滤镜支持丰富样式 |
| **BGM 混音** | ✅ 95% | 音量/淡入淡出可完美实现 |
| **简单转场** | ✅ 80% | fade/slide/dissolve 可实现，复杂 3D 转场有限 |
| **标题卡片动画** | ⚠️ 60% | 可实现静态标题卡，复杂动画需额外开发 |
| **动态贴纸/Emoji** | ❌ 不可 | 需要特殊处理 |

**差距处理方案：**

```
┌─────────────────────────────────────────────────────────────────┐
│                     FFmpeg 与 剪映效果差距处理                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  方案 1: 直接复用片头片尾（推荐）                                  │
│  ├── 剪映导出片头片尾为独立 MP4 文件                              │
│  └── FFmpeg 只拼接裸视频片段，不重新生成片头片尾                   │
│  → 效果 100% 一致                                                │
│                                                                  │
│  方案 2: 静态字幕替代动画效果                                      │
│  ├── 剪映动态字幕动画 → FFmpeg 静态字幕烧录                       │
│  └── 用户验收时如发现差距，可人工在剪映微调                        │
│                                                                  │
│  方案 3: 人工补调（可接受）                                        │
│  ├── 系统输出半成品 → 剪映二次编辑                                │
│  └── 只需微调，无需从头剪辑                                       │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

**推荐工作流：**

```
剪映制作模板
    │
    ├─→ 导出片头片尾 MP4 文件 ✅
    │
    └─→ 导出模板配置 JSON（字幕样式/转场参数）
              │
              ▼
    ┌─────────────────────────────────┐
    │  系统读取配置                    │
    │  • 裸视频片段拼接               │
    │  • 字幕烧录（样式复刻 90%）     │
    │  • 台标水印叠加                 │
    │  • BGM 混音                    │
    └───────────────┬─────────────────┘
                    │
                    ▼
    ┌─────────────────────────────────┐
    │  输出半成品视频                  │
    └───────────────┬─────────────────┘
                    │
         ┌──────────┴──────────┐
         ▼                      ▼
    ┌─────────┐          ┌─────────┐
    │ 直接发布 │          │ 剪映微调 │（如需精细调整）
    │ (大多数) │          │ (少数)   │
    └─────────┘          └─────────┘
```

**总结：**
- **片头片尾**：剪映导出 MP4 → FFmpeg 直接拼接，**100% 复刻**
- **字幕/水印/BGM**：FFmpeg 可实现 **90-95%** 复刻度
- **复杂动画**：建议直接在剪映微调（工作量远小于从头剪辑）

#### 3.4.3 字幕处理流程（方案 E）

**问题**：原始视频没有字幕，需要从音频提取并展示

**方案 E 中的处理方式**：字幕由剪映渲染，系统只需生成字幕配置

| 步骤 | 操作 | 责任方 |
|------|------|--------|
| 1 | 语音识别：Whisper/FunASR 提取音频 → 字幕文字 + 时间戳 | 系统 |
| 2 | 样式获取：从剪映模板提取字幕样式（字体/颜色/位置） | 系统（从 JSON 读取） |
| 3 | 生成字幕轨道：按剪映格式生成字幕 JSON 配置 | 系统 |
| 4 | 剪映渲染：用户导入草稿，字幕自动应用样式 | 剪映（自动） |
| 5 | 导出视频：用户点击导出，剪映完成最终烧录 | 剪映（用户操作） |

**技术实现**：

```python
# 1. 语音识别（使用 FunClip 或 Whisper）
from video.funclip_wrapper import full_transcribe_pipeline

result = full_transcribe_pipeline(
    video_path="forum.mp4",
    model_size="base",
    language="zh"
)
# 返回：字幕列表 [{"start": 0.0, "end": 5.0, "text": "今天我要分享的是..."}]

# 2. 生成剪映字幕轨道 JSON
subtitle_clip = {
    "id": "subtitle_001",
    "start_time": 3000,  # 毫秒
    "end_time": 8000,
    "content": "今天我要分享的是...",
    "style": {
        "font": "STHeitiMedium",  # 从剪映模板获取
        "font_size": 36,
        "color": "#FFFFFF",
        "background": "#00000080"
    }
}
```

**方案 A/B（FFmpeg 烧录）的处理方式**：

如果使用 FFmpeg 直接烧录：

```python
# 1. 语音识别生成 SRT 字幕文件
result = full_transcribe_pipeline(...)
srt_content = result.srt_content  # Whisper 输出 SRT 格式

# 2. 用 FFmpeg 烧录字幕
ffmpeg -i input.mp4 -vf "subtitles=subtitle.srt:force_style='FontName=STHeitiMedium,...'" output.mp4
```

**两种方案对比**：

| 方案 | 字幕效果 | 实现复杂度 | 推荐度 |
|------|----------|-----------|--------|
| **方案 E（剪映渲染）** | 100% 剪映效果 | 低 | ⭐⭐⭐⭐⭐ |
| 方案 A/B（FFmpeg 烧录） | 90% 复刻度 | 高 | ⭐⭐⭐ |

#### 3.4.2 自动化包装流程
```
片段拼接 → 片头注入 → 片尾注入 → 台标叠加 → 字幕生成 → 转场添加 → BGM 混音 → 导出
```

#### 3.5.4 方案 C：FFmpeg 模拟剪映效果

当无法直接解析剪映文件时，通过逆向分析剪映效果参数，用 FFmpeg 实现等效输出。

**字幕样式对应**：
```bash
# 剪映字幕样式 → FFmpeg 字幕滤镜
# 字体: STHeitiMedium
# 字号: 36px (1080p 基准)
# 颜色: #FFFFFF
# 背景: #00000080 (半透明黑色)

ffmpeg -i input.mp4 -vf "
  subtitles=subtitle.srt:
  force_style='FontName=STHeitiMedium,
               FontSize=36,
               PrimaryColour=&HFFFFFF&,
               BackColour=&H80000000&,
               BorderStyle=1,
               Alignment=2'
" -c:a copy output.mp4
```

**台标水印对应**：
```bash
ffmpeg -i input.mp4 -i logo.png -filter_complex "
  [1:v]scale=100:-1[logo];
  [0:v][logo]overlay=W-w-20:20:format=auto:alpha=0.8
" output.mp4
```

**转场效果对应**：
```bash
# 淡入淡出 (crossfade)
ffmpeg -i clip1.mp4 -i clip2.mp4 -filter_complex "
  [0:v]fade=t=out:st=2.5:d=0.5[v1];
  [1:v]fade=t=in:st=0:d=0.5[v2];
  [v1][v2]xfade=transition=fade:duration=0.5:offset=2.5
" -c:v libx264 -crf 18 -preset fast output.mp4
```

#### 3.5.6 方案 E：系统生成草稿 JSON → 剪映小助手导入（推荐 ⭐⭐⭐⭐⭐）

**原理**：系统生成符合剪映格式的草稿 JSON，通过**剪映小助手**导入剪映，剪辑人员一键导出即可获得完美成品。

- ✅ **100% 保留剪映效果**，无任何差距
- ✅ 剪映作为渲染引擎，发挥其特长
- ✅ 系统只需生成正确的 JSON，无需逆向实现复杂特效
- ✅ 用户操作极简：导入 → 导出

## 9. 方案 E 验证计划

### 9.1 验证目标

**核心问题**：系统能否生成符合剪映格式的 `.jap` 草稿文件，用户导入剪映后能正常渲染？

### 9.2 验证步骤

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 1 | 在剪映桌面端制作一个简单的包装模板 | 片头 + 裸视频片段 + 片尾 |
| 2 | 导出该模板的草稿 JSON 文件 | 获取真实的剪映草稿结构 |
| 3 | 分析草稿 JSON 结构 | 提取关键字段：时间线、素材路径、字幕样式 |
| 4 | 用 Python 编写 JAPGenerator | 根据真实结构生成草稿 JSON |
| 5 | 将生成的 JSON 导入剪映 | 验证剪映能否正确识别 |
| 6 | 在剪映中导出视频 | 验证成品效果是否正确 |

### 9.3 验证所需素材（需客户提供）

| 素材 | 说明 | 用途 |
|------|------|------|
| 片头视频 | MP4，3秒 | 验证 video track |
| 测试视频片段 | MP4，10-30秒 | 验证内容片段 |
| 片尾视频 | MP4，4秒 | 验证 outro track |
| 台标水印 | PNG 透明背景 | 验证 watermark |
| 背景音乐 | MP3 | 验证 audio track |
| 字幕内容 | SRT 或文本 | 验证 text track |

### 9.4 剪映草稿 JSON 获取步骤

剪映桌面端**没有**直接的"导出草稿 JSON"功能，但草稿文件存储在本地，可通过以下方式获取：

#### 步骤 1：定位剪映草稿存储位置

```
Windows 草稿目录：
%APPDATA%\CapCut\User Data\Projects\vos\

macOS 草稿目录：
~/Library/Application Support/CapCut/User Data/Projects/vos/
```

#### 步骤 2：在剪映中创建模板工程

1. 打开剪映桌面端
2. 新建项目，命名为「论坛包装模板验证」
3. 按顺序添加：
   - 片头视频（拖到时间线开头）
   - 测试视频片段（拖到时间线中间）

#### 步骤 4：提取草稿 JSON

`draft.jap` 文件本质是**压缩的 JSON**，可以用以下方式解压：

**方法 A：直接重命名（Windows）**
```
1. 右键 draft.jap
2. 选择「重命名」
3. 将 .jap 改为 .zip
4. 双击打开 ZIP，找到里面的 JSON 文件
5. 复制 JSON 内容到文本编辑器
```

**方法 B：用 Python 解压**
```python
import zipfile
import json

with zipfile.ZipFile('draft.jap', 'r') as zip_ref:
    # 列出 ZIP 内容
    print(zip_ref.namelist())

    # 读取 JSON 文件（通常叫 project.json 或类似名称）
    for name in zip_ref.namelist():
        if name.endswith('.json'):
            with zip_ref.open(name) as f:
                data = json.load(f)
                print(json.dumps(data, indent=2, ensure_ascii=False))
```

### 9.5 关键技术点

**1. 剪映草稿 JSON 结构逆向**

需要从真实草稿中提取：
- `project_id` / `name` / `duration` / `aspect_ratio`
- `tracks[].type` (video/audio/text)
- `tracks[].clips[].id` / `start_time` / `end_time` / `source`
- `transitions[].from` / `to` / `type` / `duration`
- `watermark.source` / `position` / `opacity`

**2. JAPGenerator 核心逻辑**

```python
class JAPGenerator:
    """剪映草稿 JSON 生成器"""

    def generate(self,
                 clips: List[VideoClip],
                 template: InternalTemplateConfig,
                 output_path: str) -> str:
        """
        生成剪映草稿 JSON
        """

    def build_video_track(self, clips: List[VideoClip]) -> dict:
        """构建视频轨道"""

    def build_text_track(self, subtitles: List[Subtitle]) -> dict:
        """构建字幕轨道"""

    def build_audio_track(self, bgm: AudioElement) -> dict:
        """构建音频轨道"""
```

**3. 素材路径处理**

剪映草稿中的素材路径是相对于草稿文件的：
```json
{
  "source": "material/intro_3s.mp4"
}
```

生成器需要：
- 将素材文件复制到 `materials/` 目录
- 生成相对路径的 JSON
